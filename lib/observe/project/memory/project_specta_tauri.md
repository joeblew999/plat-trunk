Load existing observe demos into a Tauri desktop shell. No demo code changes needed.

**Why:** Tauri becomes a fourth runtime (alongside browser, bun, CF Workers) that shells the existing demo workers. The same plat-observe Rust crate runs as WASM in the webview AND natively in the Tauri process — both verifiable in one session.

**How to apply:** When ready to add desktop shell or test native vs WASM parity.

## Architecture — Tauri as demo shell

```
Tauri app (demo-tauri/)
  ├── src-tauri/main.rs
  │   ├── spawns demo1 bun process → :3333
  │   ├── spawns demo2 bun process → :3334
  │   └── tauri-specta commands: start/stop workers, native tail, native scrub
  │
  └── WebviewWindow → http://localhost:3333
      (same demo UI, zero changes, same Rust WASM running in browser)
```

## Key properties
- Demos work standalone in terminal (bun demo1/bun.ts) — unchanged
- Demos work in Tauri webview — same URL, same code, same WASM
- plat-observe crate runs twice simultaneously:
  - WASM inside webview (browser context)
  - Native in Tauri process (tauri-specta commands)
- Native vs WASM parity testable in same session

## Tauri-specific commands (native side only)
```rust
#[tauri::command] #[specta::specta]
fn spawn_demo(port: u16) -> Result<(), String>   // start bun worker

#[tauri::command] #[specta::specta]
fn tail_logs(ports: Vec<u16>) -> Vec<LogEntry>   // native log tail

#[tauri::command] #[specta::specta]
fn native_scrub(json: String) -> String          // plat-observe native
```

## Folder structure
```
lib/observe/
  demo-tauri/
    src-tauri/
      src/main.rs      ← spawn workers, tauri-specta commands
      Cargo.toml       ← plat-observe (workspace dep), tauri v2, tauri-specta v2
    src/
      main.ts          ← loads webview at localhost:3333
      bindings.ts      ← generated by tauri-specta (not hand-written)
    tauri.conf.json
```
