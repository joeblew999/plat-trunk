## Remaining

### Etag merge-with-retry → @plat/sync/worker

Truck's POST /sync handler has a merge pattern: load with etag → merge → conditional save → retry on conflict → fallback to unconditional save. This is generic — any sync consumer with concurrent writers needs it.

**Extract**: `mergeWithRetry(store, modelId, incomingDoc, wasm)` function in `ts/worker/handler.ts`.
**Truck keeps**: manifest actor name updates (truck-specific), SSE presence enrichment.

### worker-relay.ts → SyncRelay

Truck's `worker-relay.ts` manages SSE with truck-specific events (`cad-command`, `sync-op`, `doc-changed`, `presence`). `SyncRelay` in `@plat/sync/adapters` handles the sync events (`doc-changed`, `sync-op`, `presence`) but NOT `cad-command` (truck-specific).

**Approach**: Truck uses `SyncRelay` for sync events + keeps its own `cad-command` handler.
**Risk**: Truck's worker-relay is tightly coupled — SSE reconnect, state broadcast on connect, Vite HMR interaction. Need careful testing.

### sync-wasm.generated.ts → createWasmAdapter

Truck's worker has `sync-wasm.generated.ts` (WASM loader) generated by `gen-adapters.ts`. Could be replaced by `createWasmAdapter` from `@plat/sync/worker`.

**Blocker**: Truck uses `syncMergeDocsWithInfo` (returns merge result + hadNewOps + op counts in one call) which is NOT in the `SyncWasmAdapter` interface. Either add it to the interface or keep the generated loader for this one extra function.
