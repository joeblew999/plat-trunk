# ADR-0014: Mapbox Vector Tiles (MVT) for Urban Context

## Status
Accepted (Updated for Passive WASM & Shared Depth)

## Context
Our platform requires a performant, 3D world map as a base layer. We serve Mapbox Vector Tiles (MVT) from PMTiles archives on Cloudflare R2. We need to render these tiles in the same WebGPU context as our CAD models to enable clash detection and altitude snapping.

## Decision
We will use the `truck` Rust kernel to parse, extrude, and render MVT data natively.

### 1. Ingestion Pipeline
*   **Decode:** Use `geozero` in Rust to decode Protobuf MVT chunks.
*   **Extrude:** Feed 2D building footprints into `truck_modeling::builder::tsweep` to create 3D B-rep `Solid` objects. This allows map buildings to participate in the same mathematical operations as CAD objects.
*   **Coordinate Sync:** MVT coordinates (Mercator) will be translated to a "Project Center" in meters relative to the CAD origin.

### 2. High-Performance Rendering (Passive WASM)
For city-scale data, we will bypass high-level `SceneObject` overhead:
*   **Rendered Trait:** Implement `truck_platform::Rendered` for the city layer.
*   **Shared Depth:** The city layer will draw into the same `RenderPass` as the CAD models, sharing the `Depth32Float` buffer.
*   **Camera Sync:** The city layer will use the 4x4 matrix provided by the Lit/Three.js "Conductor" via `cadCommand('set_camera')` (See **ADR-0013**).

## Consequences

### Positive
*   **Unified World:** Map buildings are "real" B-rep objects, enabling altitude snapping for drones and collision detection with CAD walls.
*   **Zero-Copy:** Parsing happens entirely in Rust; binary map data never touches the JavaScript heap.
*   **Visual Correctness:** Shared depth buffer prevents z-fighting between the city and the CAD model.

### Negative / Risks
*   **Memory Usage:** Extruding thousands of buildings into full B-reps is memory-intensive.
*   **Mitigation:** Implement aggressive Level of Detail (LOD) and buffer recycling for distant tiles.
